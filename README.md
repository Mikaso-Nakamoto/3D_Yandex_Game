# Мерж Арена 3D

3D-арена-шутер со **слиянием оружия** для Яндекс Игр. Survivor-like: игрок
управляет только движением, оружие стреляет само по ближайшей цели, волны врагов
нарастают, между волнами выбирается один перк из трёх.

Главный хук — **merge**: два одинаковых куба оружия одного тира сливаются
в оружие тира выше (до 6-го). Это одновременно петля прогрессии внутри забега
и основной источник rewarded-показов.

> Статус: **играбельный прототип**. Ядро геймплея, баланс и платформенный слой
> готовы; до отправки на модерацию остаётся шаг MVP (см. «Дорожная карта»).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173 — играть
npm run verify     # все проверки: баланс + аудит API + headless-симуляция
npm run zip        # собрать dist и упаковать в ZIP для Консоли + проверка требований
```

Отдельно:

```bash
npm run check      # симуляция 60 забегов: баланс волн, оружия, перков, дропа
npm run audit      # сверка перекрёстных ссылок между модулями с реальным API
npm run sim        # headless-прогон настоящего игрового цикла (~76 c игры)
```

Управление: `WASD` / стрелки / `HJKL`, на телефоне — джойстик в любой точке
ниже верхней четверти экрана. `Esc` или `P` — пауза.

## Технологии

| Решение | Почему |
|---|---|
| Three.js (r186), без игрового движка | 635 КБ на весь бандл против десятков МБ у Unity WebGL. Лимит Яндекс Игр — 100 МБ распакованного, но реальная цель — 5–20 МБ: долгая загрузка режет конверсию. |
| Вся графика процедурная | Ноль внешних ассетов. Нет проблем с лицензиями и с требованием «данные не должны грузиться со сторонних хостов». |
| Весь звук — WebAudio-синтез | 0 байт в архиве. |
| Коллизии — окружности в плоскости XZ + равномерная сетка | Физический движок не нужен: 120 врагов и 300 снарядов держат 60 FPS. |
| Пулы объектов и мешей | Никаких аллокаций в рантайме — критично для мобильного веба. |
| HUD — DOM поверх canvas | Crisp-текст на любом DPI без атласа шрифта в архиве. |

**Размер текущей сборки: 0.63 МБ распакованного, 0.16 МБ в ZIP.**

```
    arena.js              пол, стены, препятствия, свет, спавн-точки
  entities/

  ui/

    yandex.js             Yandex Games SDK v2: реклама, облачные сохранения, лидерборды
```

### Платформенный слой

Игровой код ничего не знает о платформе — он обращается к адаптеру
(`init`, `ready`, `gameplayStart/Stop`, `rewarded`, `interstitial`,
`loadData/saveData`, `submitScore`). Адаптер выбирается сам: на домене Яндекса
или при `?platform=yandex` подключается `yandex.js`, иначе `web.js`.

Это значит, что публикация на Playhop, CrazyGames или Poki — это **ещё один
файл-реализация**, а не переписывание игры.

`yandex.js` уже реализован и закрывает обязательные пункты требований:
`YaGames.init()`, `LoadingAPI.ready()`, `GameplayAPI.start()/stop()`,
`player.setData/getData` с fallback в localStorage для гостей, вызовы
`showFullscreenAdv` и `showRewardedVideo` с обязательной паузой звука и
геймплея на время показа.

## Тестирование без браузера

Браузера в среде разработки нет, поэтому вместо «проверить глазами» сделаны
три уровня автоматических проверок (`npm run verify`):

**1. `balance-check.mjs` — симуляция экономики забега (3039 проверок).**
Разыгрывает 60 забегов по тем же правилам, что и игра: шансы дропа, смещение
к уже имеющимся типам оружия, логика слияния и замены слота, выбор перков.
Сравнивает доступный DPS игрока с DPS, нужным чтобы успевать зачищать волну.

**2. `api-audit.mjs` — сверка перекрёстных ссылок (189 обращений).**
Собирает реальный API `Game` и 13 подсистем и проверяет каждое обращение
к ним из других модулей. Ловит класс багов, который статически не виден:
`game.something is not a function`. Ложные срабатывания отсечены явно
(имена файлов в импортах, одноимённые локальные поля, платформенный слой).

**3. `runtime-sim.mjs` — headless-прогон настоящего игрового цикла (88 проверок).**
Запускает реальный `Game` на 76 секунд игрового времени (4578 кадров)
с настоящей `THREE.Scene`, ареной, игроком, врагами, снарядами, пикапами,
оружием, волнами и эффектами. Подставные только DOM, Canvas2D, WebGL-рендерер,
WebAudio и `requestAnimationFrame`. Каждый кадр проверяются инварианты:
нет NaN в координатах и HP, никто не вышел за арену, пулы не переполняются.
Прогоняются все состояния: меню → бой → слияние → пикапы → выбор перка →
пауза → уход со вкладки → смерть → повторный забег → деградация качества.

Важная деталь: кадры ведутся с уступкой event loop каждый тик, потому что
в браузере между вызовами `requestAnimationFrame` стек освобождается и
микрозадачи выполняются. Полностью синхронный прогон никогда не дал бы
выполниться continuation'у после `await adapter.interstitial()` — и экран
выбора перка открывался бы пустым. Симультанно это выглядело бы как баг игры,
хотя было бы расхождением теста с реальностью.

Единственная правка прод-кода ради тестируемости — необязательный параметр
`createRenderer` в конструкторе `Game`: в браузере он не передаётся.

## Баланс

Баланс не подбирается на глаз — он проверяется симуляцией. Что она уже
поймала и как это исправлено:

| Проблема | Решение |
|---|---|
| Провал сложности на волнах 13–21 (нагрузка 0.09) — игра превращалась в прогулку, игрок уходил | HP врагов растёт как `n^2.1`, а не линейно. Нагрузка теперь 0.33–0.85 на всех 40 волнах. |
| 90% кубов оружия уходило «в пустоту»: при фиксированном 1-м тире дропа после заполнения слотов лут обесценивался, и слияний было 12 вместо 20+ | Тир дропа привязан к **слабейшему** оружию игрока, а не к номеру волны; 85% дропа совпадает с уже имеющимся типом. Слияний стало 23 за забег, 6 из них — к 10-й волне. |
| Переполнение слотов ощущалось как «подобрал и ничего не получил» | Куб честно конвертируется в монеты с частицами и всплывающим текстом. |
| Накопительный «заряд слияния» (гипотеза) | **Отброшен по данным симуляции**: доводил средний тир до потолка 6.0 уже к 20-й волне и обрывал прогрессию. |

Целевая кривая: средний тир оружия 2.2 (волна 10) → 2.9 (20) → 4.9 (40),
то есть прогрессия растёт весь забег и не упирается в потолок раньше времени.

## Экономика: на что рассчитывать

Формула дохода: `DAU × ARPDAU`, где `ARPDAU = (eCPM × показов на игрока) / 1000`.

Разработчику идёт **50%** дохода Яндекса (лицензионное соглашение, п. 8.1).
Порог выплаты — 3000 ₽, выплаты раз в месяц.

| Ориентир | Значение |
|---|---|
| eCPM для гиперказуалок / мидкора | $3–8 / $8–20 |
| ARPDAU для шутеров-арен | $0.02–0.08 |
| Реалистично с первой игры за первые 2 недели в «Новинках» | 3–6 тыс. ₽ при ~5000 игроков |
| Что нужно для ~$500/мес | ~3000 DAU при ARPDAU $0.01 |

Важно: медианная игра почти не зарабатывает. Деньги делаются на **портфеле**
из 5–10 игр на одном каркасе и на возвращаемости, а не на одном релизе.
Поэтому каркас и тесты баланса здесь важнее, чем polish первой версии.

Оформление для выплат: самозанятость в РФ — самый простой путь (налог 4–6%,
договор по единой лицензионной схеме заключается прямо в Консоли, отдельная
регистрация в РСЯ не нужна).

## Ограничения платформы, которые уже учтены в коде

- ZIP, `index.html` в корне, имена файлов без пробелов и кириллицы — проверяет `npm run zip`
- ≤100 МБ распакованного — фактически 0.63 МБ
- SDK обязателен даже без монетизации — `platform/yandex.js`
- Монетизация обязательна для модерации — вызовы рекламы в коде есть
- Прогресс не должен теряться после перезагрузки — `player.setData/getData` + localStorage fallback
- Игра доступна без регистрации — гостевой режим с локальным сохранением
- Никаких внешних ссылок, сторонних платёжных и рекламных SDK
- Интерактивный ИИ запрещён — в игре его нет
- Нет системной прокрутки, свайп-обновления и контекстного меню в игровой области
- Игра не должна быть дубликатом другой игры каталога — механика merge + survivor-like в 3D с собственной визуальной стилистикой
- Рейтинг ниже 30 три недели подряд — игру снимают с публикации, поэтому лидерборд и возврат игроков в приоритете MVP
